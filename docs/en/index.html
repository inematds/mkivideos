The workflow

Submit → queue → generate

Each request becomes a job. The worker picks up one at a time and spawns an autonomous agent session that produces the video from start to finish.

Get notified on Telegram + see it in the dashboard. Submit more whenever you like.

Why it exists

One engine, not a silo

⚖️

1 at a time, by design

Video rendering saturates the CPU. The queue serializes (concurrency = 1, FIFO) and manages the workflow—you can submit jobs whenever you like.

🔌

Host-agnostic

Ports & adapters: the core doesn't know which bot/DB exists. Runs on openpcbot, openclaw, hermes… or standalone.

📡

Telegram + dashboard + CLI

Control it with /mkivideos, track it on the dashboard :3141, or run mkivideos run without a bot.

🧩

Covers the ecosystem

explainer · demo · INEMA courses — and a larger catalog of skills, engines, and AI generators.

🛟

Doesn't block

A failed job becomes failed and the queue keeps moving. Orphaned jobs from a restart are recovered at boot.

⚡

GPU rendering

HyperFrames with --gpu --browser-gpu (NVENC) and automatic fallback to CPU.
